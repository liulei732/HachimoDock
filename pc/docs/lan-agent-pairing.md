# Wi‑Fi 设备配对

1. 让电脑和 Wi‑Fi 6 设备连接同一个可信局域网。
2. 在客户端打开「其它设置」中的 Wi‑Fi 设备配对，扫描并选择设备。
3. 检查设备名称，确认配对后可在客户端读取状态和同步 Agent 信息。

未配置的设备可以接受同一局域网内的首次配对。请在家用或受信任的办公网络完成配对。更换电脑时，先在设备上解除配对。只删除电脑侧记录时，设备仍保留原有配对。

首次使用无线控制或固件升级前，请把 USB 数据线连接到这台电脑，并在客户端打开 Wi‑Fi 配对设置完成有线授权。之后可通过 Wi‑Fi 调节音量、配置按键、安装组件和升级固件。USB 在线时客户端优先使用 USB。设备断开 USB 数据连接后仍需要供电。

配对后的设备更换 IP 时，客户端会重新发现并验证设备身份。设备固件已是最新时，升级页显示「已最新」。USB 和 Wi‑Fi 升级使用同一套板型与芯片修订版匹配规则。

ESP32-P4-Pico 使用 USB 连接。自行开发或集成设备时，请参考[设备协议](../../firmware/protocol.md)。

配对后，同一局域网内设备换 IP 时，客户端会重新发现设备，并使用原配对密钥验证身份后更新地址。

「读取设备状态」通过原配对密钥查询设备的固件版本、启动身份和网络校时状态。
此查询只读取快照，不会建立 USB 绑定或提交设备写操作。客户端只在收到认证
通过的响应后展示结果。设置打开且 USB 已连接时也会更新独立的无线状态。
超过 15 秒未核实的在线状态会在下次轮询或窗口重新获得焦点时失效。
可在状态读取超时后点击「刷新状态」。附近设备扫描结果在 150 秒后过期，需要重新扫描并选择设备。

## USB 一次授权与无线控制

首次 Wi‑Fi 配对允许状态读取和 Agent 同步。无线安装、重启、音量调整和升级需要先用 USB 验证同一设备。打开电脑的 Wi-Fi 配对设置，桌面端会自动完成有线授权。授权的是当前电脑持有的那把配对密钥，设备重启后继续有效。设备上的「解除配对」同时撤销无线控制。后续操作直接从电脑发起，无需在设备上确认。USB 在线时，桌面控制使用 USB。USB 断开后，Wi-Fi 控制可使用当前配对。

USB 验收入口是 `lan/trust`，响应为 `lan/trust-status`，使用原生 USB 当前路由或板上的 USB Serial/JTAG、USB 转串口入口。挑战请求发 `{requestId}`。成功响应的 `challenge` 是 36 个字节的小写十六进制，依次为 16 字节随机数、16 字节 ASCII 启动 ID、4 字节大端配对代次。使用当前本地配对密钥对**解码后的挑战字节**计算 HMAC-SHA256。在同一有线连接上于 5 秒内发 `{requestId, proof}`，`proof` 为 64 位小写十六进制字符。电脑会先确认 USB 挑战的启动 ID 与经认证的 LAN 状态一致。挑战一次性使用，固件验证有线来源、配对代次和启动 ID，并把与当前密钥绑定的标记写入 NVS。LAN 无授权入口，状态查询可读取 `controlTrusted`。

### 无线安装 PetUI 组件

点击「选择组件并安装」。桌面校验所选归档及其指纹，使用 USB 同一套资源编译器生成板端文件。新固件通过认证状态的 `componentBundle` 宣告支持模式 `14`。可安装设备运行器允许的 WASM、图像、精灵表、语音库、采样、短视频和分块大图。电脑扩展与其他仅用于桌面发行的文件留在归档中，流程只发布设备组件。旧固件沿用模式 `9` 安装小型声明式组件。 模式 `14` 把 `component.json`、`negative-screen.json` 和 `share.json` 随包纳入文件清单及 SHA‑256。设备从不超过 8 KiB 的有效组件清单提取最多 47 字节的版本和可选分类，并随目录事务保存。旧目录或超出此范围的字段显示未知。模式 `9` 只下发按钮和运行配置。

模式 `14` 的初始请求是 16 字节启动 ID。设备以加密 `[1]` 确认 USB 信任和启动身份后，同一 socket 依次交换以下记录。每帧为 2 字节大端正文长度、AES-GCM 密文和 16 字节 tag。长度参与 AEAD 认证，nonce 第一个字节为请求 `2` 或应答 `3`，末尾四字节为从零开始的同一大端序号。

| 记录 | 明文 |
|---|---|
| 开始 | `1, idLen:u8, fileCount:u8, totalBytes:u32 BE, SHA-256:32B, componentId` |
| 分块 | `2, fileIndex:u8, offset:u32 BE, fileBytes:u32 BE, pathLen:u8, path, bytes` |
| 提交 | `3` |

总量上限 16 MiB、128 个文件、4,352 帧。路径按字节排序，每块最多 4,096 字节。清单 SHA‑256 对每个排序后的文件依次纳入路径字节、一个 NUL、4 字节小端文件长度和完整文件内容。单帧等待上限 4 秒，提交上限 55 秒，连接从开始计时最多 360 秒。逐帧等待认证应答，`1` 表示本步接受，`0` 表示拒绝，`2` 表示持久提交结果未确认。开始后暂存只归当前 LAN 会话。旧 USB 暂存、同 ID 已安装组件和已提交目录均受保护。目录写入前检测到断连、撤销或超时会关闭暂存。结果不明时通过组件列表核对。桌面不会重发任何记录。传输期间该设备的 LAN 监听器串行处理此连接，其他 LAN 请求在会话结束后恢复。

### 无线重启

读取设备状态后点击「请求无线重启」。模式 `10` 的正文只有状态查询得到的 16 字节启动 ID。原生协议工作线程持有主运行时状态锁并检查忙碌条件后，调用 `pet_p4_diagnostics_schedule_reboot`。加密的 `1` 表示已安排重启，`0` 表示拒绝。电脑只发送一次请求，并用原密钥读取状态。只在看到新的有效启动 ID 时报告设备重新上线，换 IP 时可重新发现候选地址再用原密钥验证。应答丢失且读到新启动 ID 时只报告启动变化。

### 无线音量

模式 `11` 携带 16 字节启动 ID、16 字节请求 ID 和 1 字节目标音量（0–100）。仅接受 USB 已授权的密钥。音量线程在设备和音频空闲时应用一次，以 DAC 回读与目标的精确匹配作为成功条件。模式 `8` 按请求 ID 只读查询结果，掉线后不会重发写入。空闲时按原逻辑保存音量。

### 实机验收

- 初次普通配对后，状态读取应成功，模式 9、10 和 11 的写入应被拒绝。通过同一 USB 连接提交正确挑战后，重新读取状态应显示 `controlTrusted: true`。旧启动 ID 的请求、错误密钥的证明、重复或过期挑战，以及从无线连接提交信任均应被拒绝。
- 拔掉 USB，用 Wi-Fi 安装一个低依赖声明式测试组件并读回组件列表。再通过模式 11 写入一个测试音量，使用相同请求 ID 读取成功结果，最后恢复原值。使用模式 10 重启，确认原密钥可认证新的启动 ID 且信任仍有效。
- 在设备上解除配对后重新配对。确认新密钥只能进行初次配对允许的状态读取和同步。

### 无线固件升级

从电脑点击「通过 Wi-Fi 更新固件」。后端根据认证连接确认的板型和芯片修订版
选择随包内置且比运行版本更新的 Wi-Fi 6 镜像。设备复用原生 A/B 安装及回滚流程，
只在新启动的分区和镜像摘要与提交回执一致且通过健康确认后报告成功。
升级期间断开不会自动重发。帧格式和核验流程见
[无线 OTA 协议](../../firmware/docs/wireless-ota-adapter.md)。
